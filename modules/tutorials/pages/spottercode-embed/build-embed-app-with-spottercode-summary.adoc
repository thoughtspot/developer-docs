:page-description: Wrap-up and next steps after building a host-scoped Liveboard and Spotter embed with SpotterCode.

Two use cases shipped: a host-scoped Liveboard and a conversational Spotter panel, both locked down and wired to real data. The pattern underneath didn't change between them, and it doesn't change for whatever you build next — a Liveboard for property managers, a Spotter embed in a mobile app, a REST job that syncs booking data on a schedule.

Every task follows the same loop:

. Write one specific, terminology-precise prompt naming the exact ThoughtSpot object and the SDK you're using.
. Let SpotterCode pull the real, current documentation reference and generate code shaped to your project.
. Review it — you're checking the code, not just accepting it.
. If something's off, narrow the prompt before assuming the tool can't do it.
