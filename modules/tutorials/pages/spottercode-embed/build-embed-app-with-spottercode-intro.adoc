Imagine you're a full-stack developer at SpotStay, a short-term rental platform.

Your goal is to give hosts a self-serve analytics view inside the SpotStay host portal, something hosts can open to see how their listings are performing,  without filing a support ticket or waiting on a data team.

Two things are on your list:

* Embed a Liveboard so hosts see occupancy, revenue, and booking trends for their own listings.
* Embed Spotter so hosts can ask follow-up questions in plain language, such as "why did my weekend bookings drop in March?", without you building a custom query interface.

You already know the Visual Embed SDK.
What you don't want to do is keep tabbing out to documentation for every parameter, event, and config option.
That's the problem SpotterCode solves, for any embedding task, not just this one.

== Why developers reach for SpotterCode

Before the build: what you're actually getting, and why it's worth the five minutes to install.

It answers from the real, current docs::
The agent calls `get-developer-docs-reference` and `get-rest-api-reference` live, instead of guessing from stale training data.
Less "why doesn't this parameter exist anymore."

It reads your project before it writes code::
Output is meant to match your existing framework and file structure, not a generic snippet you have to retrofit.

It covers the whole lifecycle::
Setup, events, filters, theming, and REST calls, so you're not switching tools between "how do I embed this" and "how do I query this via API."

It stays current::
Defaults to the latest SDK version and can flag breaking changes, which matters more than it sounds once you're maintaining an embed across ThoughtSpot version bumps.

It works the same way across Cursor, Claude Code, and VS Code::
Learn the prompting pattern once, use it in whichever IDE your team standardizes on.

== Before you start: configure your ThoughtSpot instance

Before any embed will render, two things have to be true: SpotStay's portal domain is allowed to connect, and the SDK knows which ThoughtSpot cluster to talk to and how to authenticate.
Skipping this is the single most common reason a first embed shows a blank frame instead of a Liveboard.

=== 1. Allowlist the portal domain

In the ThoughtSpot UI, an admin or developer-privileged user goes to *Develop* > *Customizations* > *Security Settings* and adds the SpotStay portal's domain (for example, `+https://portal.spotstay.com+`) to the CSP and CORS allowlists.
Without this, the browser blocks the embed regardless of how correct the code is.

[NOTE]
====
*This is a one-time setup step:* it's an admin/config task, not something SpotterCode generates. Worth doing before you write a single line of embed code, so you aren't debugging a CORS error and assuming it's your code.
====

=== 2. Get the cluster hostname

SpotStay's ThoughtSpot instance lives at a specific hostname.
For a Cloud instance, it looks like `team2.thoughtspot.cloud`.
If you're not sure where to find it, ask SpotterCode:

[source]
----
How do I find the hostname of my ThoughtSpot application instance?
----

=== 3. Choose an auth type

The tutorial-friendly option is `AuthType.None`: it prompts for a ThoughtSpot login at runtime and is fine for local development.
It is not what ships to hosts in production.
Before you decide, ask SpotterCode to lay out the real options:

[source]
----
What authentication types does the Visual Embed SDK support,
and which one is recommended for a production embed with external users?
----

[NOTE]
====
*What you'll get back:* `AuthType.None` for testing only. Trusted Authentication (server-side token exchange) is the recommended pattern for production deployments, especially for external, non-ThoughtSpot-licensed users like SpotStay's hosts.
Setting up Trusted Auth means your backend issues a token. SpotterCode can help scaffold that server-side piece too, but it's a separate ask from the embed code itself.
====

=== 4. Initialize the SDK once, at the app root

Prompt for the `init()` call before touching any individual embed component:

[source]
----
Show me how to initialize the Visual Embed SDK in a React app using Trusted Authentication,
with a fallback note on AuthType.None for local development.
----

SpotterCode returns:

[source,javascript]
----
import { init, AuthType } from '@thoughtspot/visual-embed-sdk';

init({
  thoughtSpotHost: 'https://spotstay.thoughtspot.cloud',
  authType: AuthType.TrustedAuthTokenCookieless, // <1>
  // authType: AuthType.None,                    // <2>
});
----
<1> Production: server-issued token. See xref:embed-authentication.adoc[Authentication] for setup.
<2> Local development only. Do not ship this.
