:page-description: Embed Spotter below the Liveboard so managers can ask follow-up questions in plain language.

Dashboard's up.
Now the second half of the ask: managers asking follow-up questions in their own words instead of hunting through Liveboard filters for "why."

[source,javascript]
----
function renderSpotter() {
  const spotterEmbed = new SpotterEmbed(container, {
    frameParams: { width: '100%', height: '100%' },
    worksheetId: 'YOUR_WORKSHEET_GUID', // <1>
  });

  spotterEmbed.on(EmbedEvent.Init, () => console.log('Spotter initializing...'));
  spotterEmbed.on(EmbedEvent.Load, () => console.log('Spotter loaded'));

  spotterEmbed.render();
}
----
<1> Copy this value from the Developer Playground. If your instance has Auto mode enabled, you don't need to lock Spotter to a single model; set `worksheetId: 'auto_mode'` and let Spotter pick the right data source per question. If your instance doesn't have this on, contact your ThoughtSpot administrator.

[NOTE]
====
*Why this step matters beyond the demo:* this is the point where the ask stops being purely mechanical.
Spotter answers from your actual model, but which model, and what "occupied" means for a listing that's mid-turnover: that context lives with you and your data team, not in any SDK default.
====
