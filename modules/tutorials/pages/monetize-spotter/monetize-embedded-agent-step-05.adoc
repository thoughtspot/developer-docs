[#open-modal]
== Open the modal from 90% usage

Ask SpotterCode to build the modal:

[source,text]
----
"Create a pop-up modal that appears in the center of the screen when a host reaches 90%
usage. Every query from 90% usage onward opens the modal. The modal tells the host they
are running out of queries and shows their current usage. Style the modal to match the
SpotStay branding."
----

Generated output in your codebase:

// TODO: Confirm with engineering that EmbedEvent.SpotterResponseComplete is the correct
// response-complete event for SpotterEmbed. It isn't documented elsewhere in these docs.
[source,typescript]
----
// src/client/usage-modal.ts
import { EmbedEvent } from '@thoughtspot/visual-embed-sdk';
import { spotterEmbed } from './spotter';

// Shape returned by your portal's /api/usage, a thin wrapper over
// GET /api/rest/2.0/ai/usage-data/user for the logged-in host.
interface UsageSummary {
  used: number;
  limit: number;
  remaining: number;
  atWarning: boolean; // used >= warning_limit
  atLimit: boolean; // used >= limit
}

async function checkUsage(): Promise<void> {
  const usage = (await fetch('/api/usage').then((r) => r.json())) as UsageSummary;
  renderUsageBadge(usage); // for example, "312 of 400 queries left"
  if (usage.atWarning || usage.atLimit) openOutOfQueriesModal(usage);
}

spotterEmbed.on(EmbedEvent.SpotterResponseComplete, checkUsage);

// Clicking Upgrade inside Spotter opens the same modal
spotterEmbed.on(EmbedEvent.SpotterUsageLimitUpgrade, checkUsage);
----

`/api/usage` is a backend endpoint in your portal. It calls the usage data API with your admin helper, because the browser can't hold an admin token.

The `SpotterUsageLimitUpgrade` payload also includes `payload.data.usageCount`, `payload.data.usageLimit`, and `payload.data.status` (`withinLimit`, `almostReached`, or `limitReached`).
Use these values if you want to word the modal differently as the host nears their limit. For more information, see xref:spotter-usage-limits.adoc#_handling_usage_limit_events[Handling usage limit events].

[#reset-monthly]
== Reset every month

ThoughtSpot doesn't reset pools on a schedule. Run a job at the start of each billing cycle that sets every host back to their plan:

[source,typescript]
----
// src/jobs/monthly-reset.ts: run at 00:00 on the 1st of each month
import { PLANS, type Plan } from '../plans';
import { tsAdmin } from '../thoughtspot/admin';

interface HostRecord { tsGuid: string; plan: Plan }

export async function resetAllPools(hosts: HostRecord[]): Promise<void> {
  await tsAdmin('POST', '/api/rest/2.0/ai/usage-data/update', {
    updates: hosts.map((h) => ({
      key: { entity_type: 'USER', entity_identifier: h.tsGuid },
      usage: 0,
      limit: PLANS[h.plan],
      warning_limit: Math.floor(PLANS[h.plan] * 0.9),
    })),
  });
}
----
