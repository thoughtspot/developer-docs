= Troubleshooting
:toc!:
:linkattrs:

:page-title: Troubleshooting
:page-pageid: monetize-spotter__troubleshooting
:page-description: Fix common issues with Spotter usage limits, usage pools, query pack purchases, and plan changes.

[cols="2,3", options="header"]
|===
| Symptom | Action

| The counter doesn't appear
| Check that you're using Visual Embed SDK 1.53.0 or later, `isEnabled` is `true`, the display mode's threshold is met, and the host has a pool.

| A host isn't metered
| The host has no pool, or has a pool with no limit. A pool without a limit makes the host unlimited.

| A host has more queries than their plan allows
| Allowances add up across every pool that applies to the host. Check the `pools` array in the `GET /api/rest/2.0/ai/usage-data/user` response.

| 403 error on usage API calls
| The token needs the cluster-level `ADMINISTRATION` privilege. `CAN_MANAGE_SPOTTER` and Org administrator privileges aren't enough.

| 400 error on a pool update
| The `entity_type` doesn't match the cluster's metering scope. Once the first pool uses `USER`, every pool must use `USER`.

| The counter doesn't change after a purchase
| Trigger `HostEvent.SpotterRefreshUsageLimit` after the pool update lands, not on the redirect. Check that the webhook received `checkout.session.completed` and passed signature verification.

| A host was credited twice
| Key each credit on the Checkout session ID.

| A plan change removed other groups
| The user update ran with the default `REPLACE` operation. Re-add the groups, and use `ADD` and `REMOVE` instead.
|===

For more troubleshooting guidance, see xref:spotter-usage-limits.adoc#_troubleshooting[Manage Spotter usage limits].
