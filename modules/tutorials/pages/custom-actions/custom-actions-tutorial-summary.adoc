:page-description: Wrap-up and next steps after adding a Flag to team custom action to an embedded Liveboard.

You've built a custom action that works across a whole Liveboard: one menu item, every chart, one callback.

== Next steps

* *Flag a whole chart instead of a point.* Set `position` to `MENU` to put the action in the *More* menu. It then sends the chart's full result set in `embedAnswerData`, which suits "this whole chart looks off."
* *Let hosts add a note.* Open a small dialog in your app before sending, so the host can say why the point looks wrong. The note goes into the Slack message alongside the data.
* *Scope more broadly.* Use `dataModelIds.modelIds` for any chart built on a Model, or `dataModelIds.modelColumnNames` (`'<model-guid>::listing_id'`) for any chart that contains a given column. See xref:code-based-custom-actions.adoc[Code based custom actions].
* *Limit who sees it.* Restrict the action to specific groups or Orgs so only hosts get it. See xref:code-based-custom-actions.adoc[Code based custom actions].
* *Add it to Spotter.* Target `CustomActionTarget.SPOTTER` with `position: MENU` so hosts can flag Spotter answers too.
* *Create actions in the ThoughtSpot UI.* Go to *Develop* > *Customizations* > *Custom actions* to create URL or callback actions that admins manage without code. See xref:custom-actions.adoc[Custom actions overview].
* *Control visibility per embed.* Pass the action's ID to `visibleActions`, `hiddenActions`, or `disabledActions` to show it in one context and hide it in another. See xref:embed-actions.adoc[Show, hide, and disable actions].
