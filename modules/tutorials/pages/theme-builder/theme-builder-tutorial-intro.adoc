Use your brand guidelines to style embedded components so they look like they were built by your team.

== The scenario

Imagine you're a full-stack developer at SpotStay, a short-term rental company. The bookings Liveboard renders inside the host portal, and Spotter answers follow-up questions. If you haven't built that yet, start with xref:build-data-driven-app-with-tse-intro.adoc[Build a data-driven app with ThoughtSpot Embedded].

The next step is making sure every embedded component matches your theme. By the end of this guide, the embedded components will be styled so cleanly that users can't tell them apart from the rest of the portal.

Follow along in code with the link:https://github.com/nrentz-ts/spottercode[SpotStay app on GitHub, window=_blank].

[#before-you-begin]
== Before you begin

Make sure you have the following:

* Developer or Admin privilege on your ThoughtSpot instance.
* A brand guidelines document. If you don't have one, use the link:https://github.com/ipsitadeshmukh-droid/TS-Embed-Resources/blob/main/Style%20Guides/SpotStay%20Style%20%26%20Branding%20Guidelines.docx[sample SpotStay brand guidelines, window=_blank].
* If your theme references externally hosted fonts, images, or stylesheets, add those source domains as trusted domains under *Develop* > *Security Settings*. For details, see xref:security-settings.adoc[Security settings].

[NOTE]
====
*Brand input*: Theme Builder's AI mode accepts natural language prompts, brand guidelines documents, and product screenshots as reference files. If you don't have brand guidelines or screenshots on hand, use the link:https://github.com/ipsitadeshmukh-droid/TS-Embed-Resources/blob/main/Style%20Guides/SpotStay%20Style%20%26%20Branding%20Guidelines.docx[sample SpotStay brand guidelines, window=_blank].
