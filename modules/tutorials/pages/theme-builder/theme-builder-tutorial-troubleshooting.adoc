= Troubleshooting
:toc!:
:linkattrs:
:sectanchors:
:page-title: Troubleshooting
:page-pageid: theme-builder__troubleshooting
:page-description: Fix common issues when styling embedded ThoughtSpot components with Theme Builder.

[cols="2,3", options="header"]
|===
| Symptom | Action

| Styling changes don't apply at all
a| Check which mechanism you used:

* CSS variables should just work.
* Selectors in `rules_UNSTABLE` can silently stop matching after a ThoughtSpot release, and a rule without `!important` loses to ThoughtSpot's own styles. See xref:css-customization.adoc[CSS customization framework].
* If you load a stylesheet with `customCSSUrl`, confirm in your browser's *Network* tab that the file actually loads. A source domain that isn't allowlisted under *Develop* > *Security Settings* is blocked. See xref:security-settings.adoc[Security settings].

| The font falls back to the system default
| Either the `@font-face` declarations are missing a font weight that ThoughtSpot renders, or the font's source domain isn't in the CSP `font-src` allowlist. `fonts.gstatic.com` is included automatically; self-hosted fonts are not. See xref:css-customization.adoc[CSS customization framework] and xref:security-settings.adoc[Security settings].

| It looked right in Theme Builder but wrong in the app
| Compare the exported JSON with what your `init()` call actually passes. A partially copied set of variables is the usual cause. Also check that you apply the theme in one place, preferably in `init()`, so every embedded component uses the same values.

| AI mode won't change something
| The setting is probably locked by a Manual mode override or an imported JSON value. Manual settings win. Either clear the manual setting or name the change explicitly in your prompt.

| Colors from my brand guidelines were ignored
| The palette was almost certainly an image inside a PDF. Write the hex values out as text, or upload the color swatches as standalone PNG files.
|===
