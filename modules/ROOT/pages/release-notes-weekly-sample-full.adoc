=== REST APIs
[cols="16%,84%a", grid=none, frame=none]
|====================
|[.badge.badge-fix-relnotes]#Fix#|Resolved an issue where updating a sensitive connection variable (such as a password or private
key) using the `REPLACE` operation via the following REST API v2.0 endpoints did not apply
the new value:

* `POST /api/rest/2.0/template/variables/update-values`
* `POST /api/rest/2.0/template/variables/{identifier}/update`

The variable appeared updated but continued to resolve to the previous value, requiring users
to perform a manual removal step before setting the new value. This issue affected variables of
type `CONNECTION_VARIABLE` with `is_sensitive: true`. The fix ensures that a `REPLACE`
operation on sensitive variables atomically removes the old value and writes the new one,
without requiring an additional API call.
|====================

[cols="16%,84%a", grid=none, frame=none]
|====================
|[.badge.badge-fix-relnotes]#Fix#|Resolved an issue where the `POST /api/rest/2.0/groups/search` API returned `null` for the
`roles` field when called by an Org Admin user. This occurred only when Role-Based Access
Control (RBAC) was enabled. The roles were correctly visible in the ThoughtSpot UI, creating an inconsistency for applications relying on the v2.0 response.

The issue was caused by the roles field population being gated exclusively on a Cluster Admin
privilege check, which excluded Org Admins with `USER_ADMINISTRATION` privileges. Org Admins
and Group Admins can now retrieve full group role details via the v2.0 API as expected.
