== Sep 07, 2026

=== New features and enhancements

This release does not introduce any new features or enhancements.

=== Improvements

[.release-notes-table, cols="3,1,1"]
|===
| Description | Product | Feature category

a|
Fixed an issue where importing a Table TML with Row-Level Security (RLS)
rules that reference columns in joined tables failed with an Invalid GUID
error or lost join paths. TML exports and imports across clusters and Orgs
now correctly preserve join path metadata for secured tables.

*Doc reference*: <Add link once this page is published>
| ThoughtSpot Cloud
| Models

a|
Fixed an issue where the *Full Edit: Collection & nested Objects* permission
granted to a group was not inherited by nested objects in that collection.
Liveboards, Answers, and sub-collections remained read-only for group
members even when the permission was correctly applied at the collection
level. The same permission granted directly to a user worked as expected.
Group-level permissions on a collection now apply to all nested objects as
intended.

*Doc reference*: <Add link once this page is published>
| ThoughtSpot Cloud
| Permissions
|===

=== Improvements

[.release-notes-table, cols="3,1,1"]
|===
| Description | Product | Feature category

a|
Fixed an issue where Snowflake connections configured with a variable-based
password could cause intermittent authentication failures and temporary
account lockouts. Connections using variable-based secret fields are now
correctly resolved before indexing queries are dispatched to Snowflake.

*Doc reference*: <Add link once this page is published>
| ThoughtSpot Cloud
| Connections

a|
Fixed an issue where Models containing derived columns with references to
deleted source columns could fail to load after a cluster upgrade. Affected
models displayed a dependency error, associated Liveboards failed to load
data, and TML editing was unavailable for the affected models. Models with
stale column references now load correctly.

*Doc reference*: <Add link once this page is published>
| ThoughtSpot Cloud
| Models

a|
Fixed an issue where the `/api/rest/2.0/template/variables/search` API
returned empty values when a `value_scope` filter specifying a user and org
identifier was included in the request. The API now correctly returns
variable values when filtered by user and org scope.

*Doc reference*: <Add link once this page is published>
| APIs and SDK
| REST API
