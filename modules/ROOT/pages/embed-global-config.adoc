= Global embed configuration
:toc: true
:toclevels: 2

:page-title: Global embed configuration
:page-pageid: embed-global-config
:page-description: Set options that apply to all embedded ThoughtSpot components on a page, and control how the SDK passes embed configuration to the embedded app.

The global embed configuration is the object that you pass to xref:init.adoc[`init()`]. Its options apply to every embedded component on the page, for example authentication, number and date formats, and appearance. Each embedded component also has its own view configuration for settings that apply to that component only. For the full list of global options, see xref:EmbedConfig.adoc[EmbedConfig].

== View configuration settings
For options that you can set in both places, such as `isDarkMode` and `additionalFlags`, the value in the view configuration takes precedence over the value in `init()`. For example, you can set `isDarkMode: true` in `init()` and `isDarkMode: false` in the view configuration of one embed to render that embed in the default appearance.

=== Global configuration properties
Pass the global configuration to `init()` when your application loads, before you create any embedded component. `thoughtSpotHost` and `authType` are required. All other properties are optional.

[source,javascript]
----
import { init, AuthType, LogLevel } from '@thoughtspot/visual-embed-sdk';

init({
    thoughtSpotHost: '<ThoughtSpot-host>',
    authType: AuthType.TrustedAuthTokenCookieless,
    getAuthToken: () => fetchAuthTokenFromYourServer(),
    isDarkMode: false,
    logLevel: LogLevel.ERROR,
});
----

The following table lists commonly used properties. For the complete list, types, default values, and the SDK and ThoughtSpot versions that support each property, see xref:EmbedConfig.adoc[EmbedConfig].

[width="100%" cols="2,5"]

|=====
|Property|Description
|xref:EmbedConfig.adoc#_thoughtspothost[`thoughtSpotHost`]|The hostname or IP address of the ThoughtSpot cluster. Required.
|xref:EmbedConfig.adoc#_authtype[`authType`]|The authentication method, such as `AuthType.TrustedAuthTokenCookieless` or `AuthType.None`. Required. For more information, see xref:embed-authentication.adoc[Authentication].

== Dark mode
Set `isDarkMode` to `true` to render embedded ThoughtSpot content in dark appearance. The default value is `false`. Your application controls the appearance of the embed, so this setting overrides the appearance preference of the signed-in user and the color scheme of the operating system.

[source,javascript]
----
init({
    thoughtSpotHost: '<ThoughtSpot-host>',
    authType: AuthType.None,
    isDarkMode: true,
});
----

To switch an open embed between dark and default appearance without reloading it, trigger `HostEvent.UpdateTheme` with an `isDarkMode` value. For example, use it to keep the embed in step with a theme switch in your application.

[source,javascript]
----
liveboardEmbed.trigger(HostEvent.UpdateTheme, { isDarkMode: false });
----

The event resolves with the applied value, such as `{ isDarkMode: false }`. If dark appearance is not available in the embed, the embed does not change, and the event rejects with an error message.

[NOTE]
====
Dark mode requires Visual Embed SDK v1.55.0 or later and ThoughtSpot Cloud 26.12.0.cl or later. For more information, see xref:EmbedConfig.adoc#_isdarkmode[isDarkMode], xref:HostEvent.adoc#_updatetheme[HostEvent.UpdateTheme], and xref:UpdateThemeRequest.adoc[UpdateThemeRequest].
====

== How the SDK passes configuration to the embedded app
The SDK has two ways to pass embed configuration to the embedded ThoughtSpot app:

* *Iframe URL (default)*: The SDK adds the configuration to the iframe URL as query parameters.
* *`postMessage`*: The SDK keeps only the parameters that the app needs at startup on the URL, and sends the rest to the app in a `postMessage` when the app loads.

You choose the method by using the `excludeConfigFromURL` flag.

[#_exclude_configuration_from_the_iframe_url]
== Configuration settings for a compact iframe URL
By default, the iframe URL includes the embed configuration. This can make the URL very long and make the values visible in the page DOM, browser tools, and proxy logs. The `excludeConfigFromURL` flag moves most of the configuration out of the URL.

If you use Visual Embed SDK v1.55.0 or later with ThoughtSpot Cloud 26.12.0.cl or later, set `excludeConfigFromURL` to `true` in the xref:EmbedConfig.adoc#_additionalflags[`additionalFlags`] object to generate a compact iframe URL.

Set the flag in `init()` to apply it to all embeds, or in the view configuration of one embed. The view configuration value takes precedence, so `false` in a view configuration turns the flag off for that embed.

[source,javascript]
----
init({
    thoughtSpotHost: '<ThoughtSpot-host>',
    authType: AuthType.None,
    additionalFlags: { excludeConfigFromURL: true },
});

// Keep the configuration of this embed on the URL
const liveboardEmbed = new LiveboardEmbed('#tsEmbed', {
    liveboardId: '<liveboard-guid>',
    additionalFlags: { excludeConfigFromURL: false },
});
----

[NOTE]
====
The `additionalFlags` object is intended for advanced use. Hence, exercise caution. 
====

=== Comparison with the flag on or off

[width="100%" cols="2,3,3"]
[options='header']
|=====
|Aspect|Flag off (default)|Flag on
|Where most configuration goes|The SDK adds it to the iframe URL as query parameters.|The SDK sends it to the embedded app in a `postMessage` when the app loads.
|Parameters on the iframe URL|The full configuration.|Only the parameters in <<_parameters_that_stay_on_the_url,Parameters that stay on the URL>>.
|URL length|Grows with the configuration and can reach browser or proxy limits.|Stays short.
|Configuration visible in the iframe URL, browser tools, and proxy logs|Yes.|Only the startup parameters.
|Flags in `additionalFlags`|Appended to the URL.|Flags that are not startup parameters are sent in the `postMessage`.
|First render|The app reads the configuration from the URL.|The app receives the configuration before it renders, so the first load does not flash the default layout.
|=====

[NOTE]
====
Regardless of this flag, the SDK sends the map form of `disabledActionReason`, which gives each disabled action its own tooltip, in the `postMessage`, because it can be too long for a URL. A string value stays on the URL.
====

=== Behavior changes
* The iframe URL no longer contains most embed configuration, such as action visibility and Liveboard display options. Scripts, proxies, or monitoring tools that read configuration from the iframe URL stop finding those values. Use the SDK embed configuration as your source for these values.
* If you do not set the flag, the SDK continues to pass the configuration on the iframe URL.

=== Pre-rendered embeds
For a pre-rendered embed, the SDK sends the configuration when it creates the embed. When you show the pre-rendered embed, the SDK sends the current configuration again, so changes that you made in the meantime take effect.
