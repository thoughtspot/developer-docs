= Custom actions

:page-title: Custom actions overview
:page-pageid: custom-action-intro
:page-description: Add custom buttons or menu items to embedded ThoughtSpot so that your application users can act on the data they analyze.

ThoughtSpot provides a set of standard menu commands and buttons, controlled via xref:embed-actions.adoc[actions].

Custom actions add a new menu item to one of the following UI elements:

* the primary menu bar
* the **More** options menu image:./images/icon-more-10px.png[the more options menu]
* the contextual menu that appears when a user right-clicks on an Answer or visualization

ThoughtSpot recommends defining custom actions in your application code, using the Visual Embed SDK. The legacy workflows for creating custom actions through the ThoughtSpot UI and REST APIs are deprecated.

include::{path}/custom-actions-legacy-note.adoc[]

== Code-based custom actions (recommended)
Code-based custom actions are custom menu items that you define within the application's code through the Visual Embed SDK.

These custom actions add a new menu item to one of the following UI elements in an Answer, Liveboard, visualization, or in the Spotter interface:

* the primary menu bar (except for Spotter)
* the **More** options menu image:./images/icon-more-10px.png[the more options menu]
* the contextual menu that appears when a user right-clicks on an Answer or visualization (not for Liveboard)

You define the target object and the placement of each action in your code, and you can scope an action to specific Orgs. To handle the data that ThoughtSpot sends when a user clicks a code-based action, add an event handler for `EmbedEvent.CustomAction`.

For more information, see xref:code-based-custom-actions.adoc[Code-based custom actions] and xref:callback-response-payload.adoc[Callback response payload].

== Custom actions through the UI (legacy)
Before 26.12.0.cl, developers and administrators created custom actions in the **Develop** > **Customizations** > **Custom actions** page of the ThoughtSpot UI. This workflow and the REST API endpoints for managing these custom actions are deprecated. Existing custom actions continue to work until June 2027.

The following articles describe the legacy workflow:

* xref:customize-actions-menu.adoc[Create and manage custom actions (legacy)]
* xref:custom-actions-url.adoc[URL actions (legacy)]

* xref:custom-actions-worksheet.adoc[Assign custom actions to a Model (legacy)]
* xref:custom-actions-edit.adoc[Set the menu position of a custom action (legacy)]

== Ways for embedding apps to receive custom actions
**Callback actions** +

* Pass data and metadata from ThoughtSpot to the embedding page as an event.
* Define them in code through the Visual Embed SDK (recommended). See xref:code-based-custom-actions.adoc#code-based-callback[Adding callback to a code-based custom action].
* Creating callback actions through the ThoughtSpot UI is deprecated. See xref:custom-actions-callback.adoc[Callback custom actions].

**URL actions** +

* POST data directly to a specific web page or API endpoint destination.
* Available only through the ThoughtSpot UI and deprecated. There is no code-based URL action. To send data to an external endpoint, use a code-based callback action and send the data from your application. See xref:custom-actions-url.adoc[URL actions (legacy)].
