===== Separate Edit controls for Liveboards and visualizations

The SDK now lets you control the *Edit* action on Liveboards and visualizations independently:

* `EmbedEvent.EditLiveboard` and `EmbedEvent.EditVisualization` +
Fire when a user selects *Edit* on a Liveboard or on a visualization. These events fire alongside `EmbedEvent.Edit`, so existing listeners continue to work.
* `HostEvent.EditLiveboard` and `HostEvent.EditVisualization` +
Trigger Edit on one surface only. `HostEvent.EditVisualization` requires a `vizId`. `HostEvent.Edit` is unchanged.
* `Action.EditLiveboard` and `Action.EditVisualization` +
Hide or turn off Edit on one surface only. `Action.Edit` continues to control both.

For more information, see xref:EmbedEvent.adoc[EmbedEvent], xref:HostEvent.adoc[HostEvent], and xref:Action.adoc[Action].

===== Liveboard load-time overrides

Use the new `liveboardOverride` option in `LiveboardEmbed` to apply filters and Parameters when the Liveboard loads.

===== New Spotter experience

You can now enable the new Spotter experience, including Spotter on Liveboards, in your embedded application. Set `spotterExperienceVersion` to `SpotterExperienceVersion.SPOTTER_2026_11` in your `SpotterEmbed`, `LiveboardEmbed`, or `AppEmbed` configuration. The `SpotterExperienceVersion` enum is exported from the SDK. The new experience is opt-in; existing Spotter embeds remain unchanged unless explicitly opted in. The property requires ThoughtSpot Cloud 26.11.0.cl or later.

If you set `spotterExperienceVersion` to a value that the SDK doesn't recognize, the embed falls back to the standard Spotter experience without an error.

For more information, see xref:embed-new-spotter.adoc[Embed the new Spotter experience].

===== Liveboard embedding

* *Contextual filtering in Liveboards* [earlyAccess eaBackground]#Early Access#
+
Liveboard filters now have a three-tier filter hierarchy : Liveboard level, tab level, and group level. You can enable this feature in embedded Liveboards using the `isScopedLiveboardFilteringEnabled` parameter in the SDK. For more information, see xref:customize-liveboard-filters.adoc#contextual-liveboard-filtering[Contextual filtering in Liveboards].

* *Host Events* +
** The xref:HostEvent.adoc#_getgroups[`HostEvent.GetGroups`] event returns group details for the Liveboard, and the `applicability` attribute on `HostEvent.UpdateFilters` and `HostEvent.UpdateParameters` scopes filter updates to a specific tab or group. For more information, see xref:embed-events.adoc[Events and app interactions].
** The xref:HostEvent.adoc#_openparameter[`HostEvent.OpenParameter`] event opens the parameter panel for a specific parameter on the Liveboard. It accepts an optional `applicability` object to scope the action to a tab or group.

* *Centralized filter modal* in Liveboards is now generally available and enabled by default on ThoughtSpot embedded instances.

* *Column security rules on Liveboards*
+
Liveboards that were previously blocked by column security rules (CSR) now open and work normally, with column security fully enforced, including in embedded Liveboards. Filter values from inaccessible columns are masked instead of blocking the Liveboard, and scheduled Liveboard deliveries apply CSR separately for each recipient. For more information, see xref:data-security.adoc#csr-liveboards[Column security rules on Liveboards].

===== Host events with page context framework

The Visual Embed SDK introduces the HostEvent V2 framework for improved handling and execution of host events in embedded ThoughtSpot experiences with multi-layer UI interactions. The v2 framework supports the page context feature, which tracks the top-most active layer in the user's current context. Developers can use this feature to route events based on the user's current context or set a specific target context for precise and predictable handling of host events.

* To enable this feature, set `useHostEventsV2` to `true`.
* To retrieve the current context, use `getCurrentContext()`.
* To set a target context for a host event, use xref:ContextType.adoc[ContextType].

For more information, refer to the xref:events-context-aware-routing.adoc[Host events documentation].
