== Version 26.9.0.sw, November 2026

=== Full application embedding

==== Navigation and home page experience [tag redBackground]#BREAKING CHANGE#
The classic V1 and V2 navigation and home page experience modes are deprecated and no longer supported. All embedded sessions now use the V3 navigation and home page experience by default. If your embed relies on the classic experience, review your implementation and test your embedded application with the V3 experience.

For more information, see link:https://developers.thoughtspot.com/docs/deprecated-features#v1-v2-exp-fullApp-embed[V1 and V2 deprecation].

==== List page experience
In full application embedded deployments with the V3 navigation and home page experience, the default list page experience is set to ListPage V3. The ListPage V3 experience provides a refreshed list layout and styling, including the following enhancements:

* The *Views* column to show the number of views for each object.
* Sorting options for the *Name*, *Author*, and *Views* columns.
* Filters that can be added by clicking the column header, without opening the filter modal. This option is available for the *Favorites*, *Views*, and *Verified* columns.

For more information, see xref:full-app-customize.adoc#_list_page_experience[List page customization].

==== Collections page options
Embed developers can now embed the *Collections* list page and set it as the default landing page using the `Page.Collections` enumeration value. They can also include *Collections* as a navigation option in the left navigation panel in full application embeds.

For more information, see xref:set-default-page.adoc#_set_the_default_page_using_pageid[Customizing default page] and xref:full-app-customize.adoc[Customize the embedded ThoughtSpot experience].

==== Browser history management
When ThoughtSpot is embedded in a host application, internal navigation pushes new entries onto the browser history stack. As a result, the browser *Back* button steps through ThoughtSpot's internal pages before returning to the host application. To override the browser history behavior and prevent users from getting trapped in back-button loops inside the embedded iframe, set `overrideHistoryState` in the Visual Embed SDK.

==== Develop page enhancements
The *Develop* page in the ThoughtSpot UI is updated with the following enhancements:

* The *Custom actions* list page now shows the code-based custom actions configured using the Visual Embed SDK.
* The REST API v1 Playground link is removed from the left navigation. This change does not affect your current integrations with REST API v1. ThoughtSpot recommends that you update your integration workflows to use REST API v2. For more information, see xref:rest-api-v1v2-comparison.adoc[REST API v1 to v2 migration].
* The menu link to the GraphQL Playground is removed from the UI.

=== Liveboard embedding

==== Liveboard enhancements
The following enhancements are introduced in Liveboard export and filtering workflows.

Embedding a personalized Liveboard view::
You can now embed a saved personalized Liveboard view using `personalizedViewId` and load it along with the `liveboardId` in your app.

Centralized filter modal [tag purpleBackground]#Early Access#::
Liveboard users can modify multiple filters and parameters in a single session using the centralized filter modal. This feature is disabled by default on ThoughtSpot embedded instances. To enable it on embedded Liveboards, set `isCentralizedLiveboardFilterUXEnabled` to `true`.

Current period inclusion in rolling date filters::
Rolling date filters with the *Last <N> <Period>* and *Next <N> <Period>* filter types support including the current period. Developers can disable, show, or hide this option using `isThisPeriodInDateFiltersEnabled` or `Action.IncludeCurrentPeriod`.

==== Liveboard downloads
Continuous Liveboard PDF export::
In PDF downloads, Liveboard tabs can now be rendered in a single page that matches the UI layout. To enable this feature, set `isContinuousLiveboardPDFEnabled` to `true` in the SDK. Setting this flag to `false` returns to the paginated PDF view.

Liveboard download in XLSX and CSV formats::
Embedded Liveboards can now be downloaded in the PDF, XLSX, and CSV file formats. To enable this feature, set the `isLiveboardXLSXCSVDownloadEnabled` parameter to `true`.

Excel exports for pivot tables::
Pivot table visualizations can now be exported to Excel format.

For more information, see xref:embed-pinboard.adoc#_liveboard_download_options[Liveboard download options].

==== Visualization edit interface within the Liveboard view
Users can now edit the underlying query of an Answer directly within the Liveboard. When this feature is enabled, the edit button appears in the floating toolbar of the Answer when the Liveboard is opened in edit mode. Clicking the edit button opens the Answer interface preloaded with the current query context of the Answer. Users can make edits and save the changes without leaving the Liveboard.

==== KPI charts in embedded Liveboards
Embedded Liveboards support advanced controls for KPI chart customization. For more information, see link:https://docs.thoughtspot.com/software/latest/chart-kpi#advanced[KPI charts].

==== Liveboard browser cache refresh
To improve load performance and reduce reload times, you can now enable the Liveboard cache option with a *Refresh* button that lets your users clear the cache and refresh visualization data when required. For more information, see xref:embed-pinboard.adoc#liveboard-data-cache[Liveboard browser cache refresh].

==== Features generally available in 26.9.0.sw
The following features, previously in Early Access, are now generally available and enabled by default on ThoughtSpot Embedded instances:

* Hide irrelevant filters (`hideIrrelevantChipsInLiveboardTabs`) +
xref:embed-pinboard.adoc#_customizing_filter_visibility[Hides filters] that are not relevant to the visualizations displayed in a tab.
* Compact header (`isLiveboardCompactHeaderEnabled`) +
Enables the compact header in embedded Liveboards. For information about breaking changes and the affected elements, see xref:embed-pinboard.adoc#compact-header[compact Liveboard header].
* Cover page filtering options (`coverAndFilterOptionInPDF`) +
Enables the *Include cover page* and *Include filter page(s)* checkboxes in the Liveboard download modal.
* Liveboard styling and grouping (`isLiveboardMasterpiecesEnabled`) +
Enables the xref:embed-pinboard.adoc#_liveboard_grouping_and_styling[Liveboard styling and grouping] feature.
* Filter interactivity (`isEnhancedFilterInteractivityEnabled`) +
Enables interactive filter chips that allow users to add, update, or remove filters in an embedded Liveboard.

=== Customization framework

==== Chart and table overrides
You can now apply visualization overrides to charts and tables generated from a search query in ThoughtSpot search and full application embedding. The `visualOverrides` property in `SearchViewConfig` and `AppViewConfig` allows developers to apply the following overrides at embed initialization time:

* Chart overrides +
Control legend visibility and position, data label display and per-column filter thresholds, regression lines, grid lines, axis range and label settings, series colors, and conditional formatting rules including font and background styling.
* Table overrides +
Control column visibility, text wrapping, row height and padding density, table theme, and column summary visibility with per-column exceptions.

For more information, see xref:viz-overrides.adoc[Configuring visualization overrides].

==== Wide logo dimension [tag redBackground]#BREAKING CHANGE#
The recommended dimensions for the wide logo displayed on the ThoughtSpot login page have changed from 330x100px to *250x50px (5:1 aspect ratio)*. Logos uploaded at the previous dimensions may appear distorted or incorrectly scaled on the login screen. If you previously uploaded a wide logo at 330x100px, re-upload it at 250x50px to ensure correct display.

For more information, see xref:customize-style.adoc#logo-change[Customize the login page logo].

=== Authentication and data security

==== Granular download privileges
The new granular download privileges that replace the single general download privilege for RBAC-enabled clusters are now generally available:

* *Can Download Visuals*: Allows downloading chart images and visual exports.
* *Can Download Detailed Data*: Allows downloading raw tabular data (CSV, XLSX).

These privileges can be assigned independently per user or group. Update the privilege assignments in your embedded application accordingly.

==== Org isolation for per-org SAML and OIDC authentication
ThoughtSpot now enforces strict Org isolation when users authenticate through a per-Org identity provider (IdP). When a per-Org IdP sends SAML or OIDC group claims that reference Orgs outside its authorized scope, ThoughtSpot silently drops those claims and records them as security audit events. This prevents an IdP administrator in one Org from using group assertions to gain unauthorized access to another Org. Existing Org memberships that were assigned manually are unaffected.

For more information, see xref:orgs.adoc#per-org-sso-isolation[SSO and Org isolation].

==== Custom app scheme allowlisting for mobile embeds
ThoughtSpot now supports adding custom app schemes such as `capacitor://localhost` and `ionic://localhost` to the CSP and CORS allowlists. This allows mobile applications built with hybrid frameworks such as Capacitor and Ionic to embed ThoughtSpot content.

For more information, see xref:security-settings.adoc#custom-app-schemes[Security settings].

=== Data management

==== Discoverability checkbox removal [tag redBackground]#BREAKING CHANGE#
The *Make this Liveboard Discoverable* checkbox is removed from the ThoughtSpot UI. Embedding applications that relied on discoverability for content visibility must review their sharing logic and update user-facing guidance for content access. For more information, see link:https://developers.thoughtspot.com/docs/deprecated-features#liveboardDiscoverable[Deprecation announcements].

==== Personalized Views TML portability
The portability of Personalized Views across environments is improved and the feature is now GA and enabled on all ThoughtSpot Embedded instances. Import operations use smart merge logic to avoid duplicating Personalized Views. The following fields are added to the Personalized View TML:

* The `author` field, which is added during export and used to assign ownership during import.
* The `obj_id` field, which provides stable cross-environment object identity.

When you import a Liveboard TML that contains Personalized Views, ThoughtSpot preserves the views that exist only in the target environment, appends new views from the imported TML, and updates the views that are present in both. The previous limit of 100 Personalized Views per Liveboard on TML import is also removed.

For more information, see xref:tml.adoc#personalized-views-portability[Personalized Views portability].

==== Collections
ThoughtSpot embedded users can now use REST APIs v2 to organize different ThoughtSpot objects into organizational containers called *Collections*. These objects can be Liveboards, Answers, data models, tables, and even other Collections.

These APIs are currently in beta and turned off by default on ThoughtSpot instances. To enable this feature on your instance, contact ThoughtSpot Support.

For more information, see xref:collections.adoc[Collections].

==== Per-org and per-user timezone control via variables
You can centrally control timezone behavior per Org and per user in embedded deployments using the new template variable `ts_user_timezone` and Variable APIs.

For multi-Org and multi-tenant environments, each tenant Org and user can be configured independently, which ensures isolation and consistency of time-based analytics across regions. Administrators can reference the timezone variable in formulas to render and filter timestamp data correctly for each embedded user, without maintaining separate content per region.

==== Timezone-aware keyword filtering
ThoughtSpot now supports resolving relative date and time keywords, such as `today`, `yesterday`, and `last 7 days`, using a configurable per-user or per-Org timezone, instead of the default timezone of the ThoughtSpot instance. This feature eliminates timezone-based inconsistencies in multi-region embedded deployments and removes the need for custom workarounds.

The timezone awareness feature is in Beta and disabled by default. To enable this feature, contact ThoughtSpot Support.

For more information, see xref:timezone.adoc[Timezone-aware keywords and filters].

=== Performance optimization

To improve the initial load performance of large Liveboards, lazy loading is now enabled by default when `fullHeight` is set to `true`. For more information, see xref:lazy-loading-fullheight.adoc[Lazy loading of Liveboard visualizations].
