For information about the REST API v2.0 changes, see the xref:rest-apiv2-changelog.adoc[REST API v2.0 changelog].\n\n== Version 1.54.0, November 2026\n\n[width=\"100%\", cols=\"1,4\"]\n|====\n|[tag greenBackground]#NEW#\na|\n[discrete]\n===== Spotter experience version\nYou can now load the updated Spotter experience introduced in ThoughtSpot 26.11.0.cl in embedded views. Set `spotterExperienceVersion` to `SpotterExperienceVersion.SPOTTER_2026_11` in the view configuration of `SpotterEmbed`, `LiveboardEmbed`, or `AppEmbed`. When this property is set, the embed loads the updated Spotter surface instead of the default conversation surface.\n\nThis property is available in SDK 1.53.0 and later and requires ThoughtSpot Cloud 26.11.0.cl or later.\n\n[source,javascript]\n----\nconst embed = new SpotterEmbed('#tsEmbed', {\n    ... // other embed view config\n    spotterExperienceVersion: SpotterExperienceVersion.SPOTTER_2026_11,\n});\n----\n\nFor more information, see xref:embed-new-spotter.adoc[Embed the new Spotter experience].\n\n|[tag greenBackground]#NEW#\na|\n[discrete]\n===== Filter and Parameter overrides on Liveboard load\n`LiveboardEmbed` now supports the `liveboardOverride` property to apply filter and Parameter values when a Liveboard loads. Specify the overrides for each data source (Model) in the `dataSourceOverride` array. Each entry can include the following arrays:\n\n* `filterQuery` +\nFilters to apply. Each item includes a `filterQueryToken` in search sentence form, such as `color = red`.\n* `parameterQuery` +\nParameter values to apply. Each item includes a `parameterQueryToken`, such as `discount = 10`.\n\nTo scope a filter or Parameter to a Liveboard tab or group, add `tabName` and `groupName` to the item. Clauses without a query token are dropped.\n\nIn an embedded Liveboard, `liveboardOverride` is the only way to set these overrides at load time. The `filter` and `parameter` URL query parameters are ignored.\n\n[source,javascript]\n----\nconst embed = new LiveboardEmbed('#tsEmbed', {\n    ... // other embed view config\n    liveboardOverride: {\n        dataSourceOverride: [{\n            dataSourceIdentifier: '<model-guid>',\n            filterQuery: [{\n                tabName: 'Sales',\n                groupName: 'Region',\n                filterQueryToken: 'color = red',\n            }],\n            parameterQuery: [{\n                parameterQueryToken: 'discount = 10',\n            }],\n        }],\n    },\n});\n----\n\n|[tag greenBackground]#NEW#\na|\n[discrete]\n===== Separate Edit actions and events for Liveboards and visualizations\nThe SDK now distinguishes the *Edit* action on the Liveboard page from the *Edit* action in the visualization menu. The existing `Action.Edit` and `EmbedEvent.Edit` continue to work and apply to both.\n\n* `Action.EditLiveboard` +\nControls the *Edit* action on the Liveboard page only.\n* `Action.EditVisualization` +\nControls the *Edit* action in the visualization menu only.\n* `EmbedEvent.EditLiveboard` +\nEmitted when a user clicks *Edit* on a Liveboard. It is emitted along with `EmbedEvent.Edit`.\n* `EmbedEvent.EditVisualization` +\nEmitted when a user clicks *Edit* on a visualization in a Liveboard. It is emitted along with `EmbedEvent.Edit`.\n* `HostEvent.EditLiveboard` +\nTriggers the *Edit* action on the Liveboard.\n* `HostEvent.EditVisualization` +\nTriggers the *Edit* action on a specific visualization in a Liveboard. Requires `vizId` in the payload.\n\n|[tag greenBackground]#NEW#\na|\n[discrete]\n===== Action IDs for Chart Settings V2\nThe following `Action` enum members control the visibility and disabled state of the menu items in Chart Settings V2:\n\n* `Action.ChartTypeSettings` +\n*Chart Type*\n* `Action.LayoutSettings` +\n*Layout*\n* `Action.ColumnSettings` +\n*Column*\n* `Action.AxisSettings` +\n*Axis*\n* `Action.DataLabelSettings` +\n*Data Label*\n* `Action.TooltipSettings` +\n*Tooltip*\n* `Action.LegendSettings` +\n*Legend*\n* `Action.DisplaySettings` +\n*Display*\n* `Action.QuerySettings` +\n*Query Details*\n* `Action.CustomSettings` +\n*Custom Action*\n* `Action.MuzeAiSettings` +\n*Muze AI*\n* `Action.RAnalysisSettings` +\n*R Analysis*\n\n|[tag greenBackground]#NEW#\na|\n[discrete]\n===== Answer edit panel visibility\nThe `hideAnswerEditPanel` property hides the answer edit panel when set to `true`. Supported in `AppEmbed` and `SearchEmbed`.\n\n|[tag greenBackground]#NEW#\na|\n[discrete]\n===== SpotterViz file upload controls\nThe `SpotterVizConfig` object supports the following properties to control file uploads in the SpotterViz chat input on embedded Liveboards and full application embeds:\n\n* `fileUploadEnabled` +\nSet to `false` to hide the file upload option. The default value is `true`.\n* `fileUploadFileTypes` +\nRestricts the file types allowed for upload to a subset of the types SpotterViz supports, for example, `['csv', 'pdf']`. Specify file extensions with or without the leading dot. Unsupported types and empty lists are ignored.\n\n|[tag greenBackground]#MODIFIED#\na|\n[discrete]\n===== Stricter payload type checking for host events in TypeScript\nFrom SDK 1.52.0, unknown fields in the payload of a known `HostEvent` fail to compile when you call `embed.trigger()`.
