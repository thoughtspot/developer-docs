= Pre-render embedded objects
:toc: true
:toclevels: 2

:page-title: Pre-render ThoughtSpot embed components
:page-pageid: prerender-embed
:page-description: Pre-render Liveboard and Spotter embed components to optimize loading time and improve the performance of your embedded application.

Pre-rendering allows your host application to load ThoughtSpot embed components in advance, before the user navigates to the page that displays them. Because the iframe content is fetched and initialized ahead of time, the embedded object appears almost instantly when shown, improving the perceived performance of your application.

The Visual Embed SDK supports pre-rendering for Liveboard and Spotter embed components.

[IMPORTANT]
====
Starting from Visual Embed SDK 1.52.0, the top-level `preRenderId`, `preRenderContainer`, and `doNotTrackPreRenderSize` properties are deprecated. Use the `preRenderConfig` object instead. The deprecated properties continue to work, but we recommend migrating to `preRenderConfig` when you update your integration. For more information, see <<preRenderConfig, PreRenderConfig object>>.
====

== How pre-rendering works

Pre-rendering a ThoughtSpot embed component involves two phases:

1. *Pre-render phase* — The SDK creates a hidden iframe and loads the ThoughtSpot component in the background. This can happen on application startup, on login, or on any early page.
2. *Show phase* — When the user navigates to the page that displays the embedded content, the SDK makes the pre-rendered iframe visible and moves it into position. Because the content is already loaded, the transition is nearly instantaneous.

The SDK tracks the size and position of the placeholder container and applies it to the pre-rendered iframe, unless size tracking is explicitly disabled via `preRenderConfig.doNotTrackPreRenderSize`.

Starting from SDK 1.52.0, use the `preRenderConfig` property on your embed view configuration to define all pre-rendering settings in a single object.

=== Properties

[width="100%"]
[options='header']
|=====
|Property |Type |Required |Description
|`preRenderId` |String |Yes |Unique identifier for the pre-rendered embed instance. The SDK uses this ID to locate and reuse the pre-rendered iframe when the component is shown.
|`preRenderContainer` |HTMLElement |No |DOM element to host the pre-rendered iframe. If omitted, the SDK creates a hidden container in the document body.
|`doNotTrackPreRenderSize` |Boolean |No |When `true`, disables automatic size tracking of the pre-render container. Default: `false`.
|`zIndex` |Number |No |Stacking order (z-index) applied to the pre-rendered iframe. Use this if the hidden pre-rendered frame overlaps elements of your host application UI.
// TODO: verify with engineering — default zIndex value when unset
|=====

=== Example

[source,JavaScript]
----
const embed = new LiveboardEmbed('#embed-container', {
  liveboardId: '<liveboard-guid>',
  preRenderConfig: {
    preRenderId: 'my-liveboard',
    preRenderContainer: document.getElementById('pre-render-host'),
    doNotTrackPreRenderSize: false,
    zIndex: 100,
  },
});
----

== Pre-render a Liveboard

=== Pre-render without data (preRenderGeneric)

Use `preRenderGeneric()` to pre-render the ThoughtSpot application shell without loading a specific Liveboard. This is useful when you want to warm up the embed early — for example, on user login — before you know which Liveboard the user will open.

[source,JavaScript]
----
// SDK 1.52.0 and later
const embed = new LiveboardEmbed('#embed-container', {
  preRenderConfig: {
    preRenderId: 'my-liveboard',
  },
});

// Load the ThoughtSpot shell in a hidden iframe
embed.preRenderGeneric();
----

.Deprecated syntax (SDK 1.51.x and earlier)
[%collapsible]
====
[source,JavaScript]
----
const embed = new LiveboardEmbed('#embed-container', {
  preRenderId: 'my-liveboard', // deprecated in 1.52.0 — use preRenderConfig
});

embed.preRenderGeneric();
----
====

=== Pre-render with data (preRender)

Use `preRender()` to pre-render a specific Liveboard, including its data. Use this when you know in advance which Liveboard the user is likely to open.

[source,JavaScript]
----
// SDK 1.52.0 and later
const embed = new LiveboardEmbed('#embed-container', {
  liveboardId: '<liveboard-guid>',
  preRenderConfig: {
    preRenderId: 'my-liveboard',
  },
});

// Load the Liveboard and its data in a hidden iframe
embed.preRender();
----

=== Show the pre-rendered component

When the user navigates to the target page, create an embed instance with the same `preRenderId` and call `showPreRender()`:

[source,JavaScript]
----
const embed = new LiveboardEmbed('#embed-container', {
  liveboardId: '<liveboard-guid>',
  preRenderConfig: {
    preRenderId: 'my-liveboard',
  },
});

// Display the previously pre-rendered iframe
embed.showPreRender();
----

To hide the component again without destroying the pre-rendered iframe, call `hidePreRender()`:

[source,JavaScript]
----
embed.hidePreRender();
----

To remove the pre-rendered iframe entirely, for example on logout, call `destroyPreRender()`:

[source,JavaScript]
----
embed.destroyPreRender();
----

== Pre-render in React

The React wrapper provides the `PreRenderedLiveboardEmbed` component for pre-rendering.

Starting from SDK 1.52.0, `PreRenderProps` accepts either the deprecated `preRenderId` prop or a `preRenderConfig` object:

[source,JSX]
----
// SDK 1.52.0 and later
import { PreRenderedLiveboardEmbed } from '@thoughtspot/visual-embed-sdk/react';

const App = () => (
  <PreRenderedLiveboardEmbed
    liveboardId="<liveboard-guid>"
    preRenderConfig={{
      preRenderId: 'my-liveboard',
      zIndex: 100,
    }}
  />
);
----

.Deprecated syntax (SDK 1.51.x and earlier)

====
[source,JSX]
----
<PreRenderedLiveboardEmbed
  liveboardId="<liveboard-guid>"
  preRenderId="my-liveboard" // deprecated in 1.52.0 — use preRenderConfig
/>
----
====

== Size tracking of pre-rendered components

By default, the SDK tracks the size of the placeholder container and resizes the pre-rendered iframe to match it. To disable this behavior — for example, if your application manages iframe dimensions itself — set `doNotTrackPreRenderSize` to `true` in `preRenderConfig`:

[source,JavaScript]
----
const embed = new LiveboardEmbed('#embed-container', {
  liveboardId: '<liveboard-guid>',
  preRenderConfig: {
    preRenderId: 'my-liveboard',
    doNotTrackPreRenderSize: true,
  },
});
----

To manually synchronize the pre-rendered iframe's style with the placeholder container, call `syncPreRenderStyle()`:

[source,JavaScript]
----
embed.syncPreRenderStyle();
----

== Attributes and methods

[width="100%"]
[options='header']
|=====
|Attribute / Method |Description
|`preRenderConfig` |Configuration object for pre-rendering. Available from SDK 1.52.0. See <<preRenderConfig, PreRenderConfig object>>.
|`preRenderId` __(deprecated)__ |Top-level unique identifier for the pre-rendered instance. Deprecated in SDK 1.52.0 — use `preRenderConfig.preRenderId`.
|`preRenderContainer` __(deprecated)__ |Top-level pre-render container element. Deprecated in SDK 1.52.0 — use `preRenderConfig.preRenderContainer`.
|`doNotTrackPreRenderSize` __(deprecated as top-level)__ |Disables automatic size tracking. Deprecated as a top-level property in SDK 1.52.0 — use `preRenderConfig.doNotTrackPreRenderSize`.
|`preRenderGeneric()` |Pre-renders the ThoughtSpot application shell without loading a specific object.
|`preRender()` |Pre-renders the embed component along with its data.
|`showPreRender()` |Displays the pre-rendered component.
|`hidePreRender()` |Hides the pre-rendered component without destroying the iframe.
|`destroyPreRender()` |Removes the pre-rendered iframe from the DOM.
|`syncPreRenderStyle()` |Synchronizes the pre-rendered iframe's size and position with the placeholder container.
|=====
