    ThoughtSpot introduces the new Spotter experience, including Spotter on Liveboards. Spotter opens in a side panel on a Liveboard and uses the entire board and its filters as conversation context. In embedded apps, the new experience is opt-in: set `spotterExperienceVersion` to `SpotterExperienceVersion.SPOTTER_2026_11` in your embed configuration. Existing Spotter embeds remain unchanged unless explicitly opted in.

    For more information, see xref:embed-new-spotter.adoc[Embed the new Spotter experience].

    [discrete]\n==== API rate limit enforcement\nThe Org-level rate limit of 50 requests per second (RPS) per Org, announced in 26.10.0.cl, is now enforced. Requests exceeding the limit receive `HTTP 429: Too Many Requests`. This applies to all public REST API v2.0 endpoints on instances with Orgs enabled and operates independently of the existing cluster-level limit of 100 RPS per client IP.\n\nFor more information, see xref:about-rest-apis.adoc#_rate_limits_for_api_requests[Rate limits for API requests].\n\n[discrete]\n==== Link Customization APIs\nTwo new REST API v2.0 endpoints allow you to manage the URL templates ThoughtSpot uses when generating shareable links. Use these APIs to redirect links in scheduled emails, Share dialogs, and alerts to your embedding application.\n\n* `POST /api/rest/2.0/customization/links/search`\n* `POST /api/rest/2.0/customization/links/update`\n\nFor more information, see xref:link-customization-api.adoc[Link Customization APIs].\n\n[discrete]\n==== Input Table APIs\n[.version-badge.new]#New# +\nThese REST API v2.0 endpoints allow you to create and manage input tables programmatically. An input table is a table that users can edit, stored in an external Cloud Data Warehouse (CDW) and linked to a ThoughtSpot model.\n\n* `POST /api/rest/2.0/input-tables/create`\n* `POST /api/rest/2.0/input-tables/{input_table_identifier}/columns/create`\n* `POST /api/rest/2.0/input-tables/{input_table_identifier}/update`\n* `POST /api/rest/2.0/input-tables/{input_table_identifier}/columns/{column_identifier}/delete`\n* `POST /api/rest/2.0/input-tables/{input_table_identifier}/delete`\n\nFor more information, see xref:input-table-api.adoc[Input Table APIs].\n\n[discrete]\n==== Spotter Usage Data APIs \nFour new REST API v2.0 endpoints allow you to manage Spotter usage pools, which control how many Spotter questions a user, user group, or Org can ask. Use these APIs to provision limits, monitor consumption, and reset usage.\n\n* `GET /api/rest/2.0/ai/usage-data/user`\n* `POST /api/rest/2.0/ai/usage-data/search`\n* `POST /api/rest/2.0/ai/usage-data/update`\n* `POST /api/rest/2.0/ai/usage-data/delete`\n\nFor more information, see xref:spotter-usage-data-api.adoc[Spotter Usage Data APIs].\n\n[discrete]\n==== Share Analyst API\nThe new `POST /api/rest/2.0/ai/shareAnalyst` endpoint allows you to update share permissions for a Spotter Analyst programmatically.\n\n[discrete]\n==== Object ID in ThoughtSpot URLs\nYou can now use an object ID (`obj_id`) instead of a GUID in ThoughtSpot URLs for Liveboards, Answers, Collections, Models, Worksheets, Tables, Views, and Connections. Because you assign the same `obj_id` to an object in every environment, links built by your host application open the correct object when switching environments. You no longer need a GUID mapping for each environment. Existing GUID-based URLs continue to work.\n\nFor more information, see xref:object-id-in-urls.adoc[Object ID in ThoughtSpot URLs]. For guidance on moving a GUID-based deployment pipeline to `obj_id`, see xref:deploy-with-tml-apis.adoc#adopting-obj-id-in-deployment-pipeline[Adopting obj_id in a deployment pipeline].\n\n[discrete]\n==== Default RBAC enablement for new clusters\nStarting with 26.11.0.cl, Role-Based Access Control (RBAC) is enabled by default on all new ThoughtSpot Cloud clusters. Existing clusters are not affected. For more information about RBAC, see xref:rbac.adoc[Role-based access control].\n\n[discrete]\n==== New locale support\nThoughtSpot now supports four additional locales for UI localization:\n\n* Turkish (`tr-TR`)\n* Polish (`pl-PL`)\n* Romanian (`ro-RO`)\n* Ukrainian (`uk-UA`)\n\nFor more information, see xref:locale-setting.adoc[Customize locale].\n\n[discrete]\n==== Host-controlled tooltip rendering\nThe Visual Embed SDK now supports host-controlled tooltip rendering for embedded charts.
