= Visual Embed SDK upgrade checklist
:toc: true
:toclevels: 2

:page-title: Visual Embed SDK upgrade checklist
:page-pageid: sdk-upgrade-checklist
:page-description: A checklist of tasks to review before and after upgrading the Visual Embed SDK to a new version.
:keywords: SDK upgrade, visibleActions, action IDs, embed upgrade, SDK version

Each new version of the Visual Embed SDK can introduce new action IDs, new configuration properties, new events, and behavioral changes. It is recommended to review these changes before upgrading, as embedded components might behave unexpectedly or look different after the upgrade.

Use this checklist every time you upgrade the Visual Embed SDK in your application.

== Before upgrading

=== Review the SDK changelog

Read the xref:api-changelog.adoc[Visual Embed SDK changelog] entry for the version you are upgrading to. For every release, check for:

* *New action IDs*: new `Action.*` enum values that were not available in your current version.
* *New configuration properties*: new parameters, options, or config objects in `LiveboardEmbed`, `SearchEmbed`, `AppEmbed`, `SpotterEmbed`, or other embed components.
* *New events*: new `EmbedEvent.*` or `HostEvent.*` values.
* *Behavior changes or deprecations*: changes to existing properties or events that may affect your current configuration.

=== Audit your visibleActions arrays

If any of your embeds use the `visibleActions` attribute, compare the new action IDs in the changelog against your current arrays.

`visibleActions` is an *allowlist*. Any new action ID introduced in the SDK is hidden by default unless you explicitly add it to the array. This means newly available UI controls, such as buttons, menu items, or settings panel entries, don't appear in your embedded view after upgrading unless you add their action IDs.

For each `visibleActions` array in your codebase:

. Cross-reference the array against the new action IDs listed in the changelog.
. Decide whether each new action is relevant to your use case.
. Add the action IDs you want to show to the array.

[TIP]
====
If your embed shows most default actions, and you only need to restrict a few, consider switching from `visibleActions` to `hiddenActions`. With `hiddenActions`, newly introduced actions are visible by default, so your embed is not affected by new action IDs in future upgrades. For more information, see xref:embed-actions.adoc#_choosing_between_visibleactions_and_hiddenactions[Choosing between visibleActions and hiddenActions].
====

=== Review your hiddenActions and disabledActions arrays

If your embeds use `hiddenActions` or `disabledActions`, check the changelog for:

* *Renamed or replaced action IDs*: if an existing action ID is deprecated and replaced by a new one, update your arrays to use the new ID.
* *Structural action IDs*: some new action IDs control structural UI surfaces (sidebars, banners, panels) and are only supported in `hiddenActions`. Review the xref:embed-actions.adoc#_actions_not_supported_in_visibleactions[Actions not supported in visibleActions] section for the current list.

=== Check for deprecated properties and events

If the changelog lists deprecated properties, plan to migrate before the properties are removed in a future release. Deprecated items are marked in the reference documentation.

== After upgrading

=== Test all embedded views

After installing the new SDK version, test your embedded components in a non-production environment before releasing to users.

For each embedded component in your application:

. Load the component and verify that all expected actions and buttons appear.
. Open nested menus (such as the *More* menu and the *Download* menu) and confirm that the expected items are visible.
. Verify that actions in `disabledActions` appear disabled and, if you set `disabledActionReason`, show the expected tooltip.
. Verify that actions in `hiddenActions` do not appear.
. If your embed uses `visibleActions`, confirm that no expected actions are missing from the view.

=== Test event listeners

If you use `EmbedEvent` listeners or `HostEvent` triggers, verify that they still fire as expected with the new SDK version. Check the changelog for any changes to event payloads.

=== Verify custom actions

If your embed uses xref:code-based-custom-actions.adoc[code-based custom actions], confirm that they still appear and function correctly after the upgrade.
